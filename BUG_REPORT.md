### BUG-05 — Categorical `K` computed as `max()+1` on 1-indexed columns, making index 0 permanently invalid
**Severity:** HIGH
**File:** `anum-forward-process/notebooks/forward_process.ipynb`
**Lines:**
```python
NUM_CLASSES_PER_CAT[col] = int(X_train[col].max()) + 1
```
**Problem:** Columns like `admission_type_id` (values 1–8), `discharge_disposition_id` (values 1–28), and `admission_source_id` (values 1–25) are **1-indexed** in the raw dataset and are never label-encoded to 0-based. Using `max()+1` gives K=9, K=29, K=26 respectively. This means embedding index **0 is never present in real data** and is never trained. 

At forward step T=999, the uniform distribution assigns probability `1/K` to every index including 0. During reverse diffusion (generation), the model can therefore produce `discharge_disposition_id=0`, which **does not exist** in the dataset and is clinically invalid. All 1-indexed categorical columns are affected.

**Fix:** Label-encode all categorical columns to 0-based before computing K:
```python
from sklearn.preprocessing import LabelEncoder
for col in CAT_COLS:
    le = LabelEncoder()
    X_train[col] = le.fit_transform(X_train[col])
    NUM_CLASSES_PER_CAT[col] = len(le.classes_)
```
Or shift values: `X_train[col] = X_train[col] - X_train[col].min()`.

### BUG-07 — Multinomial diffusion formulation diverges from the TabDDPM paper
**Severity:** HIGH
**File:** `anum-forward-process/notebooks/forward_process.ipynb`
**Problem:** The paper (Kotelnikov et al., ICML 2023) uses **absorbing-state categorical diffusion**, where each category can only transition to a special MASK token and never to another real category. Anum's implementation uses **uniform-mixing diffusion**:
```python
probs = a_bar_expanded * one_hot + (1.0 - a_bar_expanded) * uniform
```
This is a different and simpler formulation. It is not wrong for a course project, but:
1. The reverse process derivation is different for absorbing vs. uniform-mixing diffusion.
2. The report claims to implement TabDDPM — a reviewer familiar with the paper will flag this.
3. The reverse step formula Rohith needs to implement must match THIS formulation (uniform-mixing), not the paper's absorbing formulation.

**Fix (for report):** Either (a) implement the absorbing-state formulation to match the paper, or (b) explicitly state in the report that you use uniform-mixing categorical diffusion (Austin et al.) instead of the absorbing-state variant from the original paper, and justify why.

### BUG-11 — Class conditioning test uses only 3 SGD steps on random noise; assertion is trivially weak
**Severity:** MEDIUM
**File:** `notebook/main.ipynb` — Cell 43 (TabDDPMDenoiser full check)
**Lines:**
```python
optimizer = torch.optim.SGD(model.parameters(), lr=0.01)
for _ in range(3):
    model.zero_grad()
    p = model(x_dummy, t_dummy, torch.zeros(BATCH, dtype=torch.long))
    F.mse_loss(p, torch.randn_like(p)).backward()
    optimizer.step()

diff = (out_y0 - out_y1).abs().mean().item()
print(f'3. Class cond   : mean |y0-y1| = {diff:.6f}   --> {"PASS" if diff > 0 else "FAIL"}')
```
**Problem:** After 3 gradient steps against *random* targets, any non-zero weight change will make `y=0` and `y=1` outputs different — this is trivially guaranteed by the random label noise, not by meaningful class learning. The test will pass even if the class embedding is wired incorrectly. The threshold `diff > 0` is also too loose.

**Fix:** A proper test verifies that the model is actually influenced by the class label, not just that weights changed:
```python
# After training on real data, the class embedding should produce
# structurally different predictions for the two classes.
# At minimum, verify the class embedding parameters are part of the
# computation graph and receive gradients.
assert model.class_emb.weight.grad is not None, "class_emb receives no gradient"
assert model.class_emb.weight.grad.abs().sum() > 0, "class_emb gradient is all zeros"
print("Class embedding gradient check: PASS")
```

### MISSING-02 — Reverse Diffusion Sampling Loop
**Severity:** CRITICAL
**Problem:** Even after the model is trained, there is no code to run the reverse diffusion process to generate new synthetic patients. The sampling algorithm requires:
1. Start from pure Gaussian noise (numeric) and uniform random categories
2. For `t = T-1` down to `0`: predict noise with denoiser → compute posterior mean → sample
3. Apply the inverse transform to recover original feature scale
4. Return a valid synthetic patient row in the same format as `X_train`

Without this, no synthetic data can be produced for SMOTE/CTGAN/TabDDPM comparison.
